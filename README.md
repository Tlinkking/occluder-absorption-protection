# Three-State Posterior Arbitration for Roadside LiDAR Background Subtraction

**Paper:** *Three-State Posterior Arbitration Protects Roadside LiDAR
Background Models from Occluder Absorption* — H Wang et al.
**Status:** Manuscript under review.

A beam-wise background-maintenance method for roadside LiDAR. Each return is
scored with a three-state (V/O/M) softmax posterior; only the V (visible
background) mass is allowed to update the background model, which reduces
the risk that occluding objects are absorbed into the background.

## Installation

- Python >= 3.9 (developed on 3.10)
- `pip install -r requirements.txt`
- External dependency: the
  [roadside-lidar-background-subtraction](https://github.com/HighwayScene/roadside-lidar-background-subtraction)
  repository is required for dataset I/O (TUMTraf-I and HighwayScene
  loaders, lane-OBB ground truth). Clone it and set `repo_path` in
  `configs/*.yaml` to the clone location. No installation of that repo is
  needed; its `src/` directory is added to `sys.path` at runtime.

## Data preparation

1. **TUMTraf-I**: available at the TUMTraf dataset page
   (<https://tum-traffic-dataset.github.io/tumtraf-i/>). Download sequence
   s03 and set `data_path` in `configs/tumtraf.yaml` to the extracted
   directory (the loader expects the repo's `gmm_split_s03` layout).
2. **HighwayScene**: available on Hugging Face
   (<https://huggingface.co/datasets/iis-esslingen/HighwayScene>). Set
   `data_path` in `configs/highwayscene.yaml` to the dataset root
   (containing `test/`).
3. **Proxy labels**:
   - HighwayScene uses the lane-OBB protocol directly (inside OBB =
     foreground); masks are recomputed on the fly, nothing to build.
   - TUMTraf-I requires the V/O/ignore proxy masks. Build them once:
     ```bash
     python scripts/prepare/generate_v_proxy.py --config configs/tumtraf.yaml
     python scripts/prepare/generate_o_proxy.py --config configs/tumtraf.yaml
     python scripts/prepare/merge_masks.py --config configs/tumtraf.yaml
     ```
     and set `masks_path` in `configs/tumtraf.yaml` to the output `masks/`
     directory. The voxel background reference needed by the V-proxy is
     shipped in `models/tumtraf_background_reference.npz`; it can be rebuilt
     with `scripts/prepare/build_background_reference.py` (requires the
     600-frame training window).
4. Initial per-beam background states are shipped in `models/` (see
   `docs/PROTOCOL.md` §2 for how they are derived).

If any dataset path cannot be expressed in the YAML files, edit the
`paths:` section of the corresponding `configs/*.yaml`; no code changes
should be necessary.

## Quick start

Run Ours on TUMTraf-I (test slice, prints metrics):

```bash
python scripts/run_tumtraf.py --config configs/tumtraf.yaml --strategy A2 --out preds_A2
```

Run the ablation / counterfactual variants:

```bash
python scripts/ablation.py --config configs/tumtraf.yaml --dataset tumtraf \
    --variants A2,A6,A7,OMP,MMP --logdir logs/
```

Reproduce the Table-1 style summary from saved predictions:

```bash
python scripts/evaluate.py --config configs/tumtraf.yaml --preds preds_A2 --table1
```

## Reproducing the paper results

| Artifact | How to regenerate |
|---|---|
| Table 1 (online methods) | `run_tumtraf.py` / `run_highwayscene.py` with `--strategy {B0,B1,B2,A2}`, then `evaluate.py --table1` |
| Table 1 update-rate row | `ablation.py --variants A2` (update_rate field); full-run values come from the runner's online accumulators |
| Table 2 (reference baselines) | gmm/qg/CFTA are run inside the external benchmark repo; this package does not re-implement them |
| Fig. 3 (main metrics) | metrics JSONs from `run_*.py` + `evaluate.py` |
| Fig. 4 / Fig. 5 (ablation, update mass) | `ablation.py --logdir logs/` then `evaluate.py` on the saved predictions |
| Frame-level CIs | `bootstrap.py --preds-a preds_A2 --preds-b preds_B2 --metric or40` |
| Proxy-label example figures | `figures/make_figures.py` (writes PDF + 300 dpi PNG next to the script) |

The plotting scripts that assemble the exact paper figures operate on the
paper's snapshot JSONs, which are not part of this package; the metrics they
visualize are regenerated by the commands above. Evaluation protocol details
(splits, constraints, bootstrap design, log subsampling) are in
`docs/PROTOCOL.md`.

## Parameters

Key entries in `configs/*.yaml` (see `docs/PROTOCOL.md` §3 for selection):

| Parameter | TUMTraf-I | HighwayScene | Meaning |
|---|---|---|---|
| `alpha` | 0.05 | 0.05 | learning rate of the beam-wise moment update |
| `eta` | 0.7 | 0.5 | update gate threshold on q_V |
| `wV` / `wO` | 2.0 / 0.5 | 2.0 / 0.5 | weight of the spatial-support feature g in ell_V / ell_O |
| `beta` | 10.0 | 0.1 | weight of the censoring term log S_B in ell_O |
| `bM` | -2.0 | -2.0 | constant bias of the M (missing) state |
| `sigma_r` | 0.05 | 0.05 | sensor range noise (m) |
| `c` | 6.0 | 6.0 | Hard-gate (B2) threshold only; unused by Ours |
